# 4H 頂齊／底齊：v1.2.13 結構優先選線（研究版）

## 為什麼修正

舊版 `selectFirstBarrier` 把所有一年內關卡混在一起：距離 <= 3 ATR、摸線 <= 8 回後，直接依距離排序。這會在「近期已確認轉折存在」的情況下，因碰線多次或距離稍遠而忽略箱體局部關卡，甚至選到幾個月前的同價舊關卡。

## 新規則（事前、不可偷看）

1. 先根據已收線 4H 找出已確認的轉折，**關卡的形成時間 `formed` 與確認時間 `confirmed` 不同**。
2. 依預測方向篩選價格前方關卡：中軌上方找現價**上方**頂齊；中軌下方找現價**下方**底齊。已突破的線可以供歷史研究，但不是「下一根是否穿越」的前方障礙。
3. **先在最近 50 根 4H** 所形成的線中選；沒有才到 150 根、450 根、最遠一年歷史。
4. 同一搜尋層級中，頂齊選現價上方**最低**一條，底齊選現價下方**最高**一條。相同價位由較近確認時間優先。
5. 不因測試超過 8 回直接刪掉箱體底齊／頂齊；保留 `episodes` 與 `crossCount` 作後續模型特徵。
6. **不因近期關卡距離 >3 ATR 就改挑更舊水平線**。該關卡仍顯示，但因 v6 舊模型選樣使用 3 ATR 限制，**超過 3 ATR 的新選線不輸出未經校準的百分比**。
7. 20:00 以前即時評估；20:00 後凍結關卡和機率，00:00 以當次鎖定的目標驗證。圖表 active 呼吸光、下方小卡與預測器共用同一選線函式。

## 重要研究限制

- 50／150／450 根是**可驗證的搜尋優先級起點**，目前尚無證據是最佳分段參數。
- 這版證明了結構選線規則與程式行為一致，**未證明更好的交易準確度，也尚未用 Pionex 歷史重做九年樣本外校準**。
- 超過 3 ATR 關卡會顯示位置但暫停給出百分比；即使低於 3 ATR，舊 v6 權重在新選線母體下也尚未完成重新校準。
- 本 ZIP 不是 live Worker API 連線實測結果。實際市場案例仍需部署後與 TradingView PIONEX:BTCUSDT.P 逐筆對比。
